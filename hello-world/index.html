既是一次复习，也方便以后换电脑时照着重做一遍。

为什么要用静态网站

传统的个人主页可能有后端、有数据库，但一个只展示内容的页面根本不需要这些。
静态网站的特点是：所有页面在部署前就已经生成成 HTML 文件，服务器只负责把文件发出去。

对比项 静态网站 动态网站
服务器压力 极低，只发文件 需要执行代码、查数据库
加载速度 快（可上 CDN） 取决于后端响应
安全性 攻击面小 需要考虑注入、越权等
费用 GitHub Pages 免费 通常需要服务器
适合场景 博客、文档、个人主页 需要登录、实时交互的系统

结论很明确：只是展示内容的话，静态网站是更省事也更快的选择。

技术选型

整套方案由三部分组成：

  1. Hexo —— 基于 Node.js 的静态站点生成器，用 Markdown 写作，一条命令生成整站
  2. Butterfly —— Hexo 的主题，界面美观、支持深色模式和代码高亮
  3. GitHub Pages —— 免费托管，推送即上线，还自带 HTTPS

一句话概括：Hexo 负责生成，Butterfly 负责好看，GitHub Pages 负责让别人看到。

踩过的坑

  • 仓库名必须严格是 <用户名>.github.io，否则 GitHub Pages 会把它当成项目站点，路径里会多一层子目录
  • 图片路径要以 / 开头（如 /img/avatar.svg），写相对路径在文章页里容易找不到
  • 改了配置记得 hexo clean，否则有时候会拿到上一次生成的缓存

小结

从空目录到一个能公网访问的个人主页，核心其实只有三件事：
写 Markdown、生成 HTML、推送到 GitHub。
剩下的美观程度，交给主题就好。
